## Findings (not failures)

- **Microsoft Store apps are not in the inventory (known limit).** Settings > Apps lists 48 apps, the CSV 16. The other 32 are Store apps (per tester). The script reads only the Uninstall registry keys (`HKLM`, `WOW6432Node`, `HKCU`); Store apps (e.g. the new Outlook, WhatsApp) are not registered there. The guide names this limit under "If it fails". For the migration this means: Store apps never show up in the report and are not mapped to Linux apps.
- **Per-user apps of other users are not collected, also as administrator.** The script reads `HKCU`, which is only the user running it (`collect/Get-Inventory.ps1:105-106`). The administrator run lists the same 16 apps, the `scope=user` ones belong to `vmadmin`. Apps that only `vmuser` installed for themselves would be missing. Not checked whether `vmuser` has any. Reading the other users' `NTUSER.DAT` would need loading their registry hives.
- **`arch=` is the registry view, not the program.** Rows from `WOW6432Node` get `arch=x86`, so "Wireshark 4.0.3 64-bit" and "Microsoft Visual C++ 2015-2022 Redistributable (x64)" show `arch=x86`. The contract (`docs/contracts/inventory-csv.md`) does not say which one `arch` means. Only matters if mapping uses `arch`.
- Some app rows have no `Path` (Notepad++, OneDrive, …) and Npcap has no `SizeMB`. Allowed by the contract (`Valid True`).
